# První čtenáři (FirstReader)

Worksheet generator for first-grade reading lessons. The first template is the monthly **Čtenářská výzva** (reading challenge) sheet:

- A4 page with an editable header.
- A main picture in the bottom quarter, placed left, center or right.
- One small picture per day of the month scattered around it, for the kids to color in. Optionally numbered 1 to 28-31 in random order, so kids find the day's picture.

Both pictures can be generated by AI (from a prompt, or by redrawing an uploaded picture as a coloring page) or uploaded as-is. AI generation is paid from a per-user credit wallet.

Admins can share their own pictures into a free library ("Knihovna zdarma") that everyone signed in can pick from.

Design spec: [`docs/superpowers/specs/2026-10-10-firstread-design.md`](docs/superpowers/specs/2026-10-10-firstread-design.md)

## Stack

- **Frontend:** React 19 + Vite + Tailwind 4, served as static assets by the Worker.
- **API:** Hono on a Cloudflare Worker (`worker/`).
- **Data:** D1 (SQLite) for users, credits, sheets and the image index. R2 for the image files.
- **Auth:** Better Auth, passwordless magic links (sent with Resend), invite-only. Admins invite people at `/admin`. Optional Sign in with Apple for invited people.
- **Image AI:** OpenAI GPT Image or Google Gemini, chosen with `IMAGE_PROVIDER`. `mock` for local work.

## Local development

```bash
npm install
cp .dev.vars.example .dev.vars        # IMAGE_PROVIDER=mock
npm run db:migrate:local
npm run make-admin -- you@example.com # your local account, as admin
npm run dev                           # http://localhost:5173
```

- **Signing in locally:** there is no email delivery without `RESEND_API_KEY`. Magic links and invitations are printed in the dev server terminal; open the link in the browser.
- **Mock provider:** `IMAGE_PROVIDER=mock` returns built-in line drawings and costs nothing. A prompt containing `[fail]` simulates a provider failure, to try the refund path.
- **npm install workaround:** `.npmrc` sets `legacy-peer-deps=true` to work around an npm 10 resolver crash on this dependency set.

## Configuration

**Vars** live in `wrangler.jsonc`, under `vars`:

| Var | Meaning |
|---|---|
| `APP_URL` | Public URL, e.g. `https://app.prvnictenari.cz`. Used by auth for links and cookies. |
| `MAIL_FROM` | Sender of the sign-in and invitation emails, on a domain verified in Resend. |
| `WELCOME_CREDITS` | Credits every new account gets once (default 5). |
| `IMAGE_PROVIDER` | `openai`, `gemini` or `mock`. |
| `OPENAI_IMAGE_MODEL` / `GEMINI_IMAGE_MODEL` | Model IDs. **Verify against the providers' current model lists before going live**; image model names change often. |
| `IMAGE_QUALITY` | OpenAI `low` / `medium` / `high`. |
| `CREDIT_COST_MAIN` / `CREDIT_COST_ICON` | Credits per generated main picture / repeated picture. |
| `PAYMENT_PROVIDER` | `stripe`, `mock` or empty. Buying credits shows only when the provider is usable: Stripe needs both Stripe secrets, the mock (credits at once, no payment) works only on localhost. |

**Secrets** are set with `npx wrangler secret put NAME` in production, and in `.dev.vars` locally:

| Secret | Meaning |
|---|---|
| `BETTER_AUTH_SECRET` | Long random string, e.g. `openssl rand -base64 32`. |
| `RESEND_API_KEY` | Sends the sign-in emails. |
| `OPENAI_API_KEY` / `GEMINI_API_KEY` | Whichever provider is active. |
| `APPLE_CLIENT_ID` / `APPLE_TEAM_ID` / `APPLE_KEY_ID` / `APPLE_PRIVATE_KEY` | Optional. Sign in with Apple, see below. The button shows only when all four are set. |
| `STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` | Optional. Buying credits, see below. Hidden until both are set. |

## Access

- **Invite-only.** An admin enters an email at `/admin`. That creates the account (with the welcome credits) and emails an invitation valid for 7 days. Its link opens `/invite`, where one button signs the person in. Only the button spends the one-time token, so mail scanners that open links first cannot. Resending replaces the previous invitation. After that, people sign in with a magic link.
- **Status** in `/admin`: *Čeká na přihlášení* until the first sign-in, then *Aktivní*.
- **Revoking access** (*Odebrat přístup*) is a Better Auth ban. It ends all of the user's sessions, and no new link is sent. Sheets and images stay. *Vrátit přístup* undoes it.
- **Admins** are users with the `admin` role. `npm run make-admin -- <email>` makes one locally, `--remote` in production, creating the user if needed. It is also the way back in if the last admin is locked out.

## Sign in with Apple

Optional second way in, next to the magic link. Setup, in the Apple Developer account (Certificates, Identifiers & Profiles):

1. **App ID** (e.g. `com.firstreader.app`): an explicit App ID with the Sign in with Apple capability. It is the primary App ID the other two items hang off.
2. **Services ID** (this is `APPLE_CLIENT_ID`, e.g. `com.firstreader.web`; it must differ from the App ID): enable Sign in with Apple and configure it with:
   - Domain: `app.prvnictenari.cz`
   - Return URL: `https://app.prvnictenari.cz/api/auth/callback/apple`
3. **Key:** create a key with Sign in with Apple enabled, linked to the App ID. Download the `.p8` file (Apple lets you download it only once). Its Key ID is `APPLE_KEY_ID`.
4. **Team ID** (`APPLE_TEAM_ID`): shown on the Membership page.
5. Set the secrets:

```bash
npx wrangler secret put APPLE_CLIENT_ID
npx wrangler secret put APPLE_TEAM_ID
npx wrangler secret put APPLE_KEY_ID
npx wrangler secret put APPLE_PRIVATE_KEY < AuthKey_XXXXXXXXXX.p8
```

How it behaves:

- **Client secret:** Apple wants a JWT signed with the `.p8` key, valid at most six months. The Worker signs a fresh one itself (30 days, renewed automatically), so there is nothing to rotate by hand.
- **Invite-only:** Apple signs in to an account an admin created at `/admin`, matched by the email Apple reports. It never creates accounts. Revoking access at `/admin` blocks Apple too.
- **First time:** Apple works once the teacher has opened the invitation or a magic link once. Until the mailbox is proven, Better Auth will not attach an Apple account, and the sign-in page says to use the email link first.
- **Same account:** Apple and the email links lead to the same account (same sheets, library and credits).
- **Hide My Email:** Apple can hand out a relay address (`…@privaterelay.appleid.com`) instead of the real one. It never matches an invite, so the sign-in page explains how to share the real email instead.
- **Local development:** Apple does not accept `localhost` return URLs, so Apple sign-in can only be tried on a real HTTPS domain. Locally, leave the four values empty and the button stays hidden.
- **Adoption:** `SELECT COUNT(DISTINCT userId) FROM account WHERE providerId = 'apple'` counts teachers who have used Apple at least once.

## Buying credits (Stripe)

Teachers buy one of three credit packs at `/credits` through Stripe Checkout (CZK, Czech page). Admins edit the packs' credits, price and label in `/admin`; there are always exactly three. Spec: `docs/superpowers/specs/2026-10-13-credit-purchase-design.md`.

Setup, test mode first:

1. In the Stripe dashboard, add a webhook endpoint `https://app.prvnictenari.cz/api/stripe/webhook` for the events `checkout.session.completed` and `checkout.session.async_payment_succeeded`. Copy its signing secret (`whsec_...`).
2. Set the secrets:

```bash
npx wrangler secret put STRIPE_SECRET_KEY
npx wrangler secret put STRIPE_WEBHOOK_SECRET
```

3. Buy a pack with a [test card](https://docs.stripe.com/testing) and check that the balance and a ledger row with reason `purchase` appear.
4. For live payments, check that CZK and the wanted payment methods are enabled, set the real prices in `/admin`, then replace both secrets with the live key and a live-mode endpoint's signing secret.

How it behaves:

- **Crediting:** credits land when the webhook arrives, which can be a moment after the teacher is back at `/credits?status=success`; the page refetches the balance. A replayed webhook never credits twice (one `credit_purchases` row per Checkout session).
- **Prices:** whole koruna, at least 15 Kč (Stripe's minimum CZK charge).
- **Refunds:** refunding in Stripe does **not** take the credits back. Remove them by hand in `/admin` if needed.
- **Local development:** `PAYMENT_PROVIDER=mock` in `.dev.vars` credits at once without paying. To try real Stripe locally, use test keys and the `whsec_...` printed by `stripe listen --forward-to localhost:5173/api/stripe/webhook`.

## Production

- **URL:** https://app.prvnictenari.cz (Workers custom domain; `workers_dev` is off so there is one origin for auth).
- **Resources:** D1 `firstread` (WEUR), R2 `firstread-images` (WEUR), cron `*/15 * * * *`.
- **Sender:** `prihlaseni@prvnictenari.cz`. The domain must be verified in Resend before deploying.
- **Landing page:** https://prvnictenari.cz is a separate static Worker (`landing/`, no build step). Deploy with `npm run deploy:landing`, after the app, so the bare domain is free.
- **Secrets:** `BETTER_AUTH_SECRET` is set. The rest go in the dashboard: Workers → firstread → Settings → Variables and Secrets.

## Deploying to Cloudflare

R2 must be enabled once per account in the dashboard (R2 Object Storage) before the bucket can be created.

1. Run `npx wrangler login`. Or, in CI or a cloud session, set `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`.
2. Create the database: `npx wrangler d1 create firstread`, then copy the printed `database_id` into `wrangler.jsonc`.
3. Create the image bucket: `npx wrangler r2 bucket create firstread-images`.
4. Apply the schema: `npm run db:migrate:remote`.
5. In `wrangler.jsonc`, set `APP_URL` and `MAIL_FROM` for the real domain.
6. Set the secrets from the table above (`npx wrangler secret put ...`).
7. **Resend:** add and verify the sending domain (it adds SPF/DKIM DNS records), then use an address on it in `MAIL_FROM`.
8. **Deploy:** every green push to `main` deploys automatically (the `deploy` job in `.github/workflows/ci.yml`: remote D1 migrations, then the app, then the landing page). It needs two GitHub Actions secrets:
   - `CLOUDFLARE_API_TOKEN`: "Edit Cloudflare Workers" template plus D1 Edit.
   - `CLOUDFLARE_ACCOUNT_ID`.
   By hand, in the same order: `npm run db:migrate:remote && npm run deploy && npm run deploy:landing`.
9. **Custom domain:** the domain's DNS zone must be on Cloudflare. If it isn't:
   - Copy every existing record first (website A/CNAME, MX, mail TXT), then switch the nameservers.
   - Then go to Workers → `firstread` → Settings → Domains & Routes → Add → Custom domain.
10. Make yourself admin with `npm run make-admin -- <your email> --remote`, sign in, then invite people and top up credits at `/admin`.

Production checks after deploy:

- `npx wrangler tail` while generating an image shows CPU time per request. The Workers free plan allows 10 ms of CPU per request; waiting on the AI provider does not count, but decoding its response does. If generation requests exceed it, switch to the Workers Paid plan.
- Generate one picture with each provider you plan to use, and print a test sheet.

## Credits

- **Storage:** the `wallets.balance` column is a cached sum of `credit_ledger`. Both change together in one D1 transaction, and `CHECK (balance >= 0)` makes an unaffordable debit fail atomically.
- **Generation:**
  1. The credit is debited before the provider is called.
  2. Any failure refunds it.
  3. A cron (every 15 min) refunds generations stuck as `pending` for 10+ minutes, e.g. a closed tab.
  4. Refunds are keyed to the generation, so they happen once.
- **Calibrating prices:** every generation stores the provider's token `usage`, so the credit price for external users can be set from measured cost:

```sql
SELECT provider, model, quality, COUNT(*) AS images,
       AVG(json_extract(usage_json, '$.total_tokens')) AS avg_openai_tokens,
       AVG(json_extract(usage_json, '$.totalTokenCount')) AS avg_gemini_tokens
FROM generations WHERE status = 'done' GROUP BY 1, 2, 3;
```

Run it with `npx wrangler d1 execute firstread --remote --command "..."`.

- **Not built yet:** payments. A Stripe purchase becomes one more ledger `reason` (`purchase`).
- **Before opening public signup:** add Cloudflare Turnstile to the sign-in form and a daily cap on welcome credits. Otherwise throwaway accounts can farm the free credits.

## Adding a worksheet template

A template is a folder in `src/templates/<id>/` plus one line in `src/templates/registry.ts`. It needs:

- `params.ts`: a zod schema and defaults for everything the teacher can change.
- `layout.ts`: a pure function from params to positioned text and image elements, in millimetres on A4. Unit-test it like `reading-challenge/layout.test.ts`.
- `Editor.tsx`: the controls. Use `ImageSlot` for pictures, which brings library, upload and AI generation along.
- `definition.ts`: ties the three together.

Preview, PDF export, saving and the image library are shared.

# FirstRead

Worksheet generator for first-grade reading lessons. The first template is the monthly **Čtenářská výzva** (reading challenge) sheet:

- A4 page with an editable header.
- A main picture in the bottom quarter, placed left, center or right.
- One small picture per day of the month scattered around it, for the kids to color in. Optionally numbered 1 to 28-31 in random order, so kids find the day's picture.

Both pictures can be generated by AI (from a prompt, or by redrawing an uploaded picture as a coloring page) or uploaded as-is. AI generation is paid from a per-user credit wallet.

Admins can share their own pictures into a free library ("Knihovna zdarma") that everyone signed in can pick from.

Design spec: [`docs/superpowers/specs/2026-10-10-firstread-design.md`](docs/superpowers/specs/2026-10-10-firstread-design.md)

## Stack

- **Frontend:** React 19 + Vite + Tailwind 4, served as static assets by the Worker.
- **API:** Hono on a Cloudflare Worker (`worker/`).
- **Data:** D1 (SQLite) for users, credits, sheets and the image index. R2 for the image files.
- **Auth:** Better Auth, passwordless magic links (sent with Resend), invite-only.
- **Image AI:** OpenAI GPT Image or Google Gemini, chosen with `IMAGE_PROVIDER`. `mock` for local work.

## Local development

```bash
npm install
cp .dev.vars.example .dev.vars        # IMAGE_PROVIDER=mock, put your email in ALLOWED_EMAILS/ADMIN_EMAILS
npm run db:migrate:local
npm run dev                           # http://localhost:5173
```

- **Signing in locally:** there is no email delivery without `RESEND_API_KEY`. The magic link is printed in the dev server terminal; open it in the browser.
- **Mock provider:** `IMAGE_PROVIDER=mock` returns built-in line drawings and costs nothing. A prompt containing `[fail]` simulates a provider failure, to try the refund path.
- **npm install workaround:** `.npmrc` sets `legacy-peer-deps=true` to work around an npm 10 resolver crash on this dependency set.

## Configuration

**Vars** live in `wrangler.jsonc`, under `vars`:

| Var | Meaning |
|---|---|
| `APP_URL` | Public URL, e.g. `https://firstread.bozkovo.org`. Used by auth for links and cookies. |
| `MAIL_FROM` | Sender of the magic-link email, on a domain verified in Resend. |
| `WELCOME_CREDITS` | Credits every new account gets once (default 5). |
| `IMAGE_PROVIDER` | `openai`, `gemini` or `mock`. |
| `OPENAI_IMAGE_MODEL` / `GEMINI_IMAGE_MODEL` | Model IDs. **Verify against the providers' current model lists before going live**; image model names change often. |
| `IMAGE_QUALITY` | OpenAI `low` / `medium` / `high`. |
| `CREDIT_COST_MAIN` / `CREDIT_COST_ICON` | Credits per generated main picture / repeated picture. |

**Secrets** are set with `npx wrangler secret put NAME` in production, and in `.dev.vars` locally:

| Secret | Meaning |
|---|---|
| `BETTER_AUTH_SECRET` | Long random string, e.g. `openssl rand -base64 32`. |
| `RESEND_API_KEY` | Sends the sign-in emails. |
| `OPENAI_API_KEY` / `GEMINI_API_KEY` | Whichever provider is active. |
| `ALLOWED_EMAILS` | Comma-separated. Only these can sign in. |
| `ADMIN_EMAILS` | Comma-separated. These can grant credits at `/admin`. |

The two email lists are secrets, not vars, so they never land in this public repo.

## Deploying to Cloudflare

R2 must be enabled once per account in the dashboard (R2 Object Storage) before the bucket can be created.

1. Run `npx wrangler login`. Or, in CI or a cloud session, set `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`.
2. Create the database: `npx wrangler d1 create firstread`, then copy the printed `database_id` into `wrangler.jsonc`.
3. Create the image bucket: `npx wrangler r2 bucket create firstread-images`.
4. Apply the schema: `npm run db:migrate:remote`.
5. In `wrangler.jsonc`, set `APP_URL` and `MAIL_FROM` for the real domain.
6. Set the secrets from the table above (`npx wrangler secret put ...`).
7. **Resend:** add and verify the sending domain (it adds SPF/DKIM DNS records), then use an address on it in `MAIL_FROM`.
8. **Deploy:** run `npm run deploy`. Or connect the repo in Workers Builds with:
   - Build command: `npm run build`
   - Deploy command: `npx wrangler deploy`
9. **Custom domain:** the domain's DNS zone must be on Cloudflare. If it isn't:
   - Copy every existing record first (website A/CNAME, MX, mail TXT), then switch the nameservers.
   - Then go to Workers → `firstread` → Settings → Domains & Routes → Add → Custom domain.
10. Sign in once, then top up accounts at `/admin`.

Production checks after deploy:

- `npx wrangler tail` while generating an image shows CPU time per request. The Workers free plan allows 10 ms of CPU per request; waiting on the AI provider does not count, but decoding its response does. If generation requests exceed it, switch to the Workers Paid plan.
- Generate one picture with each provider you plan to use, and print a test sheet.

## Credits

- **Storage:** the `wallets.balance` column is a cached sum of `credit_ledger`. Both change together in one D1 transaction, and `CHECK (balance >= 0)` makes an unaffordable debit fail atomically.
- **Generation:**
  1. The credit is debited before the provider is called.
  2. Any failure refunds it.
  3. A cron (every 15 min) refunds generations stuck as `pending` for 10+ minutes, e.g. a closed tab.
  4. Refunds are keyed to the generation, so they happen once.
- **Calibrating prices:** every generation stores the provider's token `usage`, so the credit price for external users can be set from measured cost:

```sql
SELECT provider, model, quality, COUNT(*) AS images,
       AVG(json_extract(usage_json, '$.total_tokens')) AS avg_openai_tokens,
       AVG(json_extract(usage_json, '$.totalTokenCount')) AS avg_gemini_tokens
FROM generations WHERE status = 'done' GROUP BY 1, 2, 3;
```

Run it with `npx wrangler d1 execute firstread --remote --command "..."`.

- **Not built yet:** payments. A Stripe purchase becomes one more ledger `reason` (`purchase`).
- **Before opening public signup:** add Cloudflare Turnstile to the sign-in form and a daily cap on welcome credits. Otherwise throwaway accounts can farm the free credits.

## Adding a worksheet template

A template is a folder in `src/templates/<id>/` plus one line in `src/templates/registry.ts`. It needs:

- `params.ts`: a zod schema and defaults for everything the teacher can change.
- `layout.ts`: a pure function from params to positioned text and image elements, in millimetres on A4. Unit-test it like `reading-challenge/layout.test.ts`.
- `Editor.tsx`: the controls. Use `ImageSlot` for pictures, which brings library, upload and AI generation along.
- `definition.ts`: ties the three together.

Preview, PDF export, saving and the image library are shared.
